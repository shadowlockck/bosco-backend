# SELF-STUDY: ПР №2.5

## Перевірка критеріїв

- `catalog/views.py` не містить HTML-рядків: сторінки повертаються через
  `render()`, а після успішного POST використовується `redirect()`.
- Порожній `/products/` показує «Товарів немає.» через `{% empty %}`.
- Після додавання товару виконується POST → redirect → повідомлення
  `messages.success()`. Повідомлення показується один раз і зникає після
  наступного оновлення сторінки.
- У шаблонах немає фільтра `|safe`. Дані, введені користувачем, залишаються
  під автоматичним екрануванням Django.

## Експеримент 1: автоекранування `<script>`

Створив товар із назвою `<script>alert(1)</script>`. У «Переглянути код
сторінки» замість виконуваного HTML відображається
`&lt;script&gt;alert(1)&lt;/script&gt;`. JavaScript не запускається, тому що
Django автоматично екранує спеціальні символи виведених змінних. Це захищає
шаблон від вставки HTML або JavaScript через поле назви товару.

## Експеримент 2: `DEBUG = False`

Запустив перевірку з `DEBUG=False`:

```bash
DEBUG=False python manage.py check
```

Конфігурація Django залишається коректною, але development-сервер не має
роздавати static-файли як у режимі розробки. Для production потрібно виконати
`collectstatic` і налаштувати окрему роздачу `STATIC_ROOT`. Після експерименту
повернув значення за замовчуванням до `DEBUG=True`.

## Експеримент 3: CSRF і відповідь 403

У DevTools перевірив форму: всередині `<form method="post">` є приховане поле
`csrfmiddlewaretoken`, а браузер отримує cookie `csrftoken`. Якщо прибрати
`{% csrf_token %}` і надіслати POST, Django відповідає HTTP 403 з текстом
`CSRF verification failed`.

CSRF-токен доводить, що POST надіслано зі сторінки, яку сформував наш Django
застосунок. Зловмисний сайт може спробувати використати cookie користувача,
але не знає правильного токена з нашої форми. `CsrfViewMiddleware` порівнює
токен форми з cookie та відхиляє запит, якщо поле відсутнє або значення не
збігаються. Тому запит без `{% csrf_token %}` завершується 403 і товар не
створюється.

автоекранування та CSRF, а також документація Django про
