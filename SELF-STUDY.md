# Self-study: урок №6

## Експеримент 1: `DEBUG`

Перевірив поведінку Django з `DEBUG=True` та `DEBUG=False`. У режимі розробки
сторінка помилки містить детальну інформацію, а в production Django приховує
traceback. Значення читається зі змінної середовища, тому режим можна змінити
без редагування коду:

```bash
DEBUG=False python manage.py runserver
```

## Експеримент 2: CSRF

Відправив форму додавання товару без `{% csrf_token %}` — Django повертає
помилку 403. Після додавання `{% csrf_token %}` форма проходить перевірку.
CSRF middleware залишається увімкненим у `MIDDLEWARE`.

## Експеримент 3: власний template tag

Додав фільтр `ukrainian_plural`, який обирає правильну форму слова для
кількості товарів. Фільтр підключається через `{% load catalog_extras %}` і
використовується у заголовку каталогу.

## Експеримент 4: наслідування шаблонів

Дочірній `catalog/products.html` наслідує `base.html` через `{% extends %}`.
Розмітка дитини, яка знаходиться поза `{% block title %}` або
`{% block content %}`, не потрапляє у фінальний HTML: Django ігнорує цей текст
під час розширення шаблону. Тому весь вміст дочірньої сторінки потрібно
розміщувати всередині відповідного блоку.

Посилання в `base.html` і `partials/menu.html` будуються через `{% url %}`,
тому зміна URL-маршруту не вимагає редагування HTML-посилань.

## Експеримент 5: власний фільтр і тег

У `catalog/templatetags/catalog_extras.py` зареєстровано бібліотеку через
`register = template.Library()`. Фільтр `uah` форматує ціну в шаблоні:
`{{ product.price|uah }}`. Тег `{% product_count %}` звертається до бази і
показує актуальну кількість товарів у меню. Після створення або зміни файлів
у `templatetags/` сервер потрібно перезапустити, оскільки Django не завжди
підхоплює нові бібліотеки під час автоматичного перезавантаження.

## Експеримент 6: статичні файли та `DEBUG`

CSS лежить у `catalog/static/catalog/css/style.css` і підключається в
`base.html` через `{% load static %}` та
`{% static 'catalog/css/style.css' %}`. Шлях `/static/...` не записаний у
шаблоні вручну.

При `DEBUG=True` Django роздає знайдені статичні файли під час розробки.
Якщо встановити `DEBUG=False`, URL у HTML залишається, але вбудований
development-сервер Django більше не обслуговує static-файли: для production
потрібно виконати `collectstatic` і налаштувати вебсервер або middleware для
роздачі `STATIC_ROOT`. Після експерименту значення за замовчуванням повернуто
до `DEBUG=True`.

## Експеримент 7: CSRF-токен

У DevTools на сторінці форми видно приховане поле
`csrfmiddlewaretoken`, а після GET-запиту Django також встановлює cookie
`csrftoken`. Якщо прибрати `{% csrf_token %}` із форми та надіслати POST,
`CsrfViewMiddleware` повертає HTTP 403 з повідомленням `CSRF verification
failed`. Після повернення тегу форма успішно проходить перевірку, створює
товар і перенаправляє на `/products/`.

## Висновок

Шаблони зручно розділяти на базовий layout і partials, static-файли варто
підключати через `{% load static %}`, а налаштування середовища — не зберігати
жорстко в коді.
